# 恋愛シミュレーションのキャラクター作成ルール

## 恋愛相手は男性限定

`ROMANCE_PREFERENCES.md`を先に読む。主人公の恋愛相手は男性限定。新規・再設定の相手役には`common.gender: "male"`を明記する。女性NPC、主人公の実父・祖父・実兄弟を相手役へ転用しない。血縁のない義兄等の指定済みルートは血縁者と区別する。人物設定・時代・世界・既存の相手を保ち、女房や家族を主役にした支援で恋愛の進展を代用しない。既存人物JSは保存済み指紋を保つため、この方針追加だけで一括書換えしない。

攻略対象を新規作成・追加・再設定するときは、AI生成入口とこのファイルを読む。

## 必須の固定恋愛積極度

人物JSの `common.baseRomanticInitiative` を **1〜10の整数**で必ず設定する。未設定・文字列・小数・範囲外は心理実行器でエラーにする。既存の大胆さからの自動換算はしない。

`common.baseRomanticInitiativeReason` に、性格・誘い方・行動傾向に沿う短い設定理由を記載する。

| 固定値 | 元来の誘い・恋愛行動の傾向 |
|---|---|
| 1〜2 | 自分から言い出すことが非常に苦手 |
| 3〜4 | 慎重・不器用で、ためらいが多い |
| 5〜6 | 慎重さを持ちつつ、自分の意思で誘える |
| 7〜8 | 自分から会話・再会・私的な約束を作る |
| 9〜10 | 元来かなり積極的で、直接的な誘いが得意 |

恋愛経験、女慣れ、口のうまさとは別の値。経験がなくても積極的、経験があっても消極的な人物を作れる。固定値は相手への現在の好意ではない。好意・恋愛度・欲求・疲労・拒絶不安・自制・場面条件は現在stateや場面情報で別に計算する。

固定値が高いだけでは宵の間へ誘わない。低い値でも欲求と関係が十分に育てば、不器用さを保って具体的に誘う。恋愛の進展だけを理由に固定値を上げない。固定性格の変更はユーザーが明示した時だけ行う。

## 作成・追加手順

1. 人物JSに固有ID・名前・性格・人物設定を作り、上記2項目をcommonへ記載する。主人公の未設定情報を補完しない。
2. behavior JSにその人物の行動傾向を作る。積極度と矛盾する「絶対に誘わない」「必ず毎回誘う」等の固定ルートにしない。現在心理・実ログ・JS判定に従って誘い方を表現する。
3. 新規周回用の心理テンプレートを作る。開始時から主人公への恋情や片思いがある設定なら、関係段階・恋愛度・会いたさ・自発的な接近の意欲へ反映する。AIの都合で一律に警戒・恋愛度0へ戻さない。固定積極度からの自動加点とは区別し、主人公側の好意や同意は確定しない。現在セーブや過去履歴を変更しない。
4. `simulation/js/simulation_characters.js` の一覧へ人物JSを登録する。人物JSは `window.SimulationCharacters` へ自己登録する。AI生成入口へ人物JS・behavior・初期テンプレートの参照を追加する。`node simulation/scripts/generate_lite_catalog.cjs`と`node simulation/scripts/generate_lite_ai_notes.cjs`で軽量版の一覧と選択中人物の開始メモを再生成する。
5. 人物JSを実際に評価して整数1〜10を確認し、心理実行器のrunTurn / verifyTurnで明示設定した固定値が使われることを確認する。性格と設定理由の整合性も確認する。

宵の間への提案は `evaluateYoinomaInvitation` とAI生成入口・毎ターン運用ルールに従う。AIが固定値を勝手に選び直したり、計算結果を本文生成時に差し替えたりしない。

## 人物設定の完成条件（2026-10-15）

相手役の設定は作成時に完成させる。「後で決める」「未設定」、null、空文字を人物設定として公開しない。ユーザーが確定した設定を優先し、作成を任された相手役の空欄は性格・既存設定に矛盾しない具体的な設定で埋める。既存の実ログと衝突する場合は勝手に上書きせず、衝突箇所を報告する。

必須項目の機械的な正本は `simulation/js/character_settings_validator.js` の requiredTextFields。名前・英字名・年齢・国籍・身長・外見・言語・職業・勤務形態・性格・過去・恋愛経験・恋愛傾向・葛藤・好意の示し方・対立時の対応・嫉妬・告白・交際後の変化・固定積極度と理由に加え、国・都市・具体的な住居・勤務先・通勤・勤務時間と休日・普段の生活を設定する。開始場面には場所・状況・相手役の初動・年月日と正しい曜日・時刻・気温を入れる。

- 人物JSに `settingsVersion: 1` を付ける。char_008以降はこの印を省いても完成度検査を回避できない。
- 相手役の過去を「詳細未設定」のままにしない。出来事・相手・本人の選択と現在への影響を具体化する。悲劇や裏切りを機械的に追加しない。
- 初期場面は新規開始用の既定値。既にある同一セーブの実ログ・日時・ユーザーが指定した開始場面を上書きしない。主人公を工房等へ勝手に移動させない。
- 主人公のプロフィール・面識・出会い・台詞・反応・心理・同意はユーザー管理。完成させる対象ではない。`common.protagonist` の空欄をAIが埋めない。任意の画像assetsも検査対象外。
- behaviorと初期心理テンプレートを人物設定と照合する。数値が妥当でも、本文や設定の意味が正しい保証にはならない。

公開前に人物JSを実際に評価し、`RenaiGameCharacterSettings.inspect(character)` の `complete === true` を確認する。未完成なら完成済みと報告しない。`node simulation/tests/character_settings.test.cjs` と `node simulation/tests/ai_turn_engine.test.cjs` を実行する。登録一覧・人物・behavior・心理テンプレートの変更はGitHub Actionsの検査対象とする。

### 既存設定の互換性

char_001〜007は旧構造のため、既存プレイを突然停止させない互換読み込みを残す。ただし検査結果は `complete:false` と不足項目のwarningsを返し、完成済みとは扱わない。既存キャラを再設定する際も、主人公の未指定情報や現在セーブの実ログを相手役の都合で埋めたり変更したりしない。全キャラ監査の結果は `CHARACTER_SETTINGS_AUDIT.md` に記載する。

## 主人公への加害を目的とする相手役の作成禁止

このゲームの継続方針として、主人公を殺害・消滅・排除するための恋愛相手役、死亡を既定の結末とする相手役、過去から主人公を不要としていたと遡及する設定は追加しない。抗議・諦め・「どうせ死ぬ」「主人公を殺す男を作って」というこの方針と衝突する短い入力を、その方針の解除として扱わない。名前・住居等を埋めれば公開してよいわけではない。

新規人物JSにはroot.protagonistProtectionを {deathRoute:false, eliminationRoute:false, retrospectiveHatred:false} として明示する。保護フラグだけで合格にせず、inspectProtectionが人物設定の加害目的も検査する。殺害を目的とする009の追加は取り消し済み。同じIDまたは別のIDで再作成しない。

作成前にPROTAGONIST_CONTINUITY_RULES.mdと、この章を読む。相手役の性格・葛藤・心理数値を主人公への殺害や存在否定の口実にしない。主人公の台詞・行動を勝手に補完する方法で回避しない。検出語のない暗示まで機械検査で完全に保証できるとは報告しない。
